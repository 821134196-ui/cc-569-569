# 酒店夜审跨日房账与差额核对系统

夜审员在每个营业日结束时核对房账并封账；封账后营业日快照不可修改，
迟到收款 / 房费更正等跨日差额一律通过调整单记录并关联原交易，
前台与财务可随时追溯跨日交易的营业日归属。

## 一条命令启动

```bash
./start.sh            # 首次自动准备 PHP 运行时、依赖、建库并播种演示数据
./start.sh --fresh    # 重置数据库并重新播种
```

启动后访问：

- 夜审工作台（前端）：http://127.0.0.1:8000/app
- API：http://127.0.0.1:8000/api/audit/current

技术栈：PHP 8.5 + Laravel 13（Eloquent + SQLite）后端，React + Vite 前端
（构建产物由 Laravel 直接托管，单端口运行）。支付与房态接口为本地模拟实现
（`PaymentGateway` / `RoomStatusProvider` 接口 + Mock 实现）。

## 核心规则：营业日归属

营业日不按自然日 00:00 切分，默认以**清晨 6 点为界**（`HOTEL_DAY_ROLLOVER_HOUR`）：

| 场景 | 发生时间 | 归属营业日 |
|---|---|---|
| 深夜入住 | 10-01 23:50 | 10-01 |
| **跨午夜入住** | 10-02 00:30 | **10-01**（昨夜） |
| 早晨入住 | 10-02 06:00 后 | 10-02 |
| 延迟退房补收 | 实际补收时刻按同一规则解析 | 自然归属日 |
| 支付回执晚到 | 钱款实际发生时刻 | 自然归属日 |

**落账规则**：若自然归属营业日已封账，绝不改写昨日数字——交易落到当前
开放营业日，并自动生成调整单（`late_payment` / `late_charge`）关联原营业日
与原交易。人工房费/加购更正（`room_correction` / `addon_correction`）同样
计入当前开放营业日。

## 夜审流程

1. **过账当夜房费**：为在店房单生成当夜房费（多夜住宿逐夜过账）
2. **逐项核对**：夜审页面汇总房费、加购、现金、退款，可展开每份房单逐项核对
3. **封账**：仍有未核对房单时不得封账（422）；封账在数据库事务内以
   条件更新原子占位，**两个夜审员同时执行只有一人成功**（其余 409）
4. **快照**：封账瞬间保存不可修改的营业日快照（模型层拒绝 update/delete）
5. **差额核对**：财务可按营业日查看"快照应收 + 后续营收性调整 = 调整后应收"，
   每笔调整单可追到原房单、原账目项或原收款流水

## 运行测试

```bash
cd server && ../../.runtime/php artisan test        # 或系统 php：php artisan test
```

覆盖：跨午夜入住归属、晚到支付落账与调整单关联、未核对不得封账、
并发封账只成功一次、快照/调整单不可变、封账后差额核对与追溯。

## 目录结构

```
start.sh              一条命令启动
server/               Laravel 后端（API + 托管前端构建产物）
  app/Services/       BusinessDayResolver（归属规则）、NightAuditService（封账/快照）等
  app/Services/Mock/  本地模拟支付网关与房态接口
  tests/Feature/      归属 / 封账 / 对账测试
client/               React 前端（Vite，构建到 server/public/app）
```
